代码编写规范（webGIS团队协作版）

声明：本编写规范专为 WebGIS 项目团队的内部协作、开发与管理制定，所有内容仅限于团队成员使用。未经项目负责人或团队授权，严禁对外公开、传播或分享。

写在前面

  1. 所有代码在比赛与开发过程中不得以任何形式外传或开源，不可在公共平台、社交媒体或其他未经授权的渠道泄露相关代码及文档；
  1. 团队所有数据（包括原始数据、分析数据、地图数据等）仅限于团队内部使用，严禁外泄，不得以任何形式透露给未经授权的个人或机构，任何数据的共享或发布必须经过团队批准；
  1. 所有源数据必须基于实测数据、开源数据集或官方授权的数据源进行获取，不得随意使用未经验证的第三方数据或AI生成的数据；如果项目需求确实需要使用模拟数据，必须提前与团队进行充分讨论和确认；
  1. 在进行数据可视化与地图制图时，不得将原始数据上传至任何AI平台或第三方工具。原始数据的上传可能造成数据泄露，严重时可能涉及法律责任；
  1. 开发过程中可以使用AI作为辅助工具，以提高开发效率，但不得将其视为唯一解决方案。开发者应保持对代码质量和业务逻辑的高度负责：
    • 开发者必须明确理解核心逻辑，在代码中提供详细的注释，尤其是在关键步骤或复杂算法处；
    • 合理使用AI工具，避免对工具产生过度依赖，能独立思考和分析问题。
  1. 所有开发成果需保存在统一仓库，定期同步代码与模板，定期检查版本管理，自觉配合开发进度与工作内容的透明化，保证团队协作的高效性。

HTML编码规范

1. 使用 HTML5 语义化标签编写文档

优先使用 HTML5 语义化标签，避免完全使用<div> 和 <span> 来替代语义化标签，除非确实没有合适的替代标签。

错误案例（完全使用div，无语义化可读性）

正确案例：

<header>
    <h1>欢迎来到我的网站</h1>
    <nav>
        <ul>
            <li><a href="#home">首页</a></li>
            <li><a href="#about">关于我们</a></li>
        </ul>
    </nav>
</header>
<main>
    <section>
        <h2>webGIS</h2>
        <p>我们提供高质量web开发服务</p>
    </section>
</main>
<footer>
    <p>&copy; 2025 xxx</p>
</footer>

2. 标签嵌套合法

所有标签必须正确闭合。避免出现不成对的标签或不符合 HTML 规范的嵌套。

错误案例：

<div>
    <p>这是一个段落，段落的内容。</a> <!-- 错误：标签未闭合 -->
    <a href="#">链接</p> <!-- 错误：<a>标签不能包含 <p> 标签 -->
</div>

正确案例：

<div>
    <p>这是一个段落，段落的内容。</p>
    <a href="#">链接</a>
</div>

3. ID与Class命名规范

ID命名：应该是唯一的，用于标识一个特定的元素；使用有意义的名称，反映该元素的作用或内容；必须遵循 kebab-case（例如：#main-header, #login-form），使用小写字母和连字符（-）。

错误案例：

<div id="MainHeader">
    <h1>网站标题</h1>
</div>

正确案例：

<div id="main-header">
    <h1>网站标题</h1>
</div>

Class命名：使用具有语义的类名，并且类名应符合 kebab-case 规范；避免使用太笼统或过于常见的类名（如：.box, .container），应尽可能具体。

错误案例：

<div class="box">
    <a href="#">首页</a>
</div>

正确案例：

<div class="nav-bar">
    <a href="#">首页</a>
    <a href="#">关于我们</a>
</div>

4. 严禁使用内联样式！！！

不要在 HTML 中使用内联样式。所有样式应放在外部 CSS 文件中，或者使用 <style> 标签内嵌 CSS（仅限小范围的样式调整）。

错误案例：
绝对绝对绝对不可以写这样的样式：

<div style="width: 100%; margin: 0 auto;">
    <h1>欢迎来到我的网站</h1>
</div>

5.规范注释

  • 文件头部注释：在每个 HTML 文件的开头添加文件描述，包括文件用途、作者、最后修改日期、版本等信息。
  • 代码段注释：对复杂的逻辑或关键代码段进行适当注释，简洁明了地解释其作用。
  • 遵循项目的注释规范，如统一注释风格、格式等（见具体样例）

推荐使用Better Comments 以及 Todo Tree两个插件，按照要求备注注释，负责人看到便会处理

文件头部样式正确案例：

<!--
  文件: index.html
  描述: 网站主页
  作者: 张三
  日期: 2025-05-01
-->
<html>
<head>
    <title>首页</title>
</head>
<body>
    <header>
        <h1>欢迎来到我的网站</h1>
    </header>
</body>
</html>

6. 文件结构与模块化

保持文件结构清晰，确保 HTML 文件结构与样式、脚本等资源文件分离,使用文件夹组织代码，按功能模块分开 HTML、CSS 和 JavaScript 文件。推荐安装vscode icons插件

推荐结构：

/project
    /css
        styles.css
    /js
        main.js
    index.html

CSS编码规范

1. 禁止使用内联样式

  • 严禁在 HTML 标签中使用内联样式（style 属性），所有样式应通过外部 CSS 文件或 <style> 标签进行定义；
  • 优先使用类名和 ID 来控制样式，保持结构与样式分离。

错误示例：

<div style="width: 100%; margin: 0 auto;">
    <h1>欢迎来到我的网站</h1>
</div>

正确示例：

<div class="container">
    <h1>欢迎来到我的网站</h1>
</div>

2. 禁止滥用 !important

  • !important 仅应在特殊情况下使用，例如当某些样式无法通过常规优先级规则覆盖时。
  • 过多使用 !important 会导致样式优先级混乱，增加维护的复杂性。
  • 使用 !important 前，应与团队成员沟通，确保其必要性和正确性。

错误案例：

.button {
    background-color: blue !important;
    color: white !important;
}

正确示例：

.button {
    background-color: blue;
    color: white;
}

/* 在某些极端情况下，如果确实需要强制覆盖，可以使用 */
.header {
    font-size: 24px !important;
}

4. 遵循 BEM（块、元素、修饰符）命名规范

（尽量保证就好，最好能列一个类名的映射表，避免其他成员使用时重复命名）

  • BEM 是一种推荐的命名方法，旨在提高 HTML 和 CSS 代码的可读性和可维护性。每个类名都应符合 block__element--modifier 的格式，避免全局样式污染。

命名示例：

/* Block */
.button {}

/* Element */
.button__icon {}

/* Modifier */
.button--primary {}

HTML 结构示例：

<button class="button button--primary">
    <span class="button__icon"></span>
    提交
</button>

避免的命名示例：

.red-button { } /* 过于具体，不具备复用性 */

5. 避免使用过度嵌套

  • CSS 选择器的嵌套层级不应超过 3 层。过多的嵌套会导致样式的复杂性增加，也影响选择器的效率。
  • 使用组合选择器和子选择器时，要保持简洁和直观。

正确示例：

.card {
    background-color: white;
}

.card__title {
    font-size: 20px;
}

错误示例：

.card .card__title .card__subtitle {
    font-size: 14px;
}

6. 尽量保持样式表结构清晰

  • 将样式表划分为多个模块，根据功能将相关的样式分开。例如，布局、排版、按钮、表单等模块应有各自的 CSS 文件，保持代码的模块化和清晰。
  • 在单个样式文件中，按以下顺序组织内容：
    1. 重置/标准化样式
    1. 全局设置（字体、颜色、背景等）
    1. 布局样式
    1. 组件样式
    1. 状态样式（如 :hover, :active 等）
    1. 辅助样式（如动画、响应式布局）

正确示例：

/* Reset styles */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

/* Global styles */
body {
    font-family: Arial, sans-serif;
}

/* Component styles */
.button {
    background-color: blue;
    color: white;
}

7. 使用相对单位而非固定单位

  • 为了提高页面的响应性，保证网页在其他平台可以正常加载，尽量使用相对单位（如 em, rem, %, vw, vh）而非固定单位（如 px）。例如，使用 rem 或 em 设置字体大小和间距。

正确示例：

body {
    font-size: 1rem;
}

.container {
    width: 80%;
}

错误示例：

body {
    font-size: 16px;
}

.container {
    width: 960px;
}

9. 注释和文档

  • 对于复杂的样式或有特别需求的代码段，添加清晰的注释。
  • 文档化 CSS 文件，特别是大型项目中，可以在每个模块或功能部分的开始处添加简短的说明。

正确示例：

/* 主要按钮样式 */
.button {
    background-color: blue;
    color: white;
}

/* 页面头部 */
header {
    background-color: black;
}

10. 响应式设计

  • 使用媒体查询来确保页面在不同屏幕尺寸下的适配。对于移动端友好的页面，应优先设计移动端布局，然后根据需要调整桌面端布局。

正确示例：

/* 基础样式 */
.container {
    width: 100%;
}

/* 小屏幕 */
@media (max-width: 600px) {
    .container {
        padding: 10px;
    }
}

/* 大屏幕 */
@media (min-width: 1200px) {
    .container {
        max-width: 1200px;
    }
}

JavaScript编码规范

代码一定要让人能看懂的，可读性优先于简洁性

保持一致性，团队统一使用 ESLint + Prettier 工具统一风格

不要有冗长复杂的逻辑嵌套的代码

1、变量声明规范

推荐使用

  • const：用于不会被重新赋值的常量（默认首选）
  • let：用于需要重新赋值的变量
  • 减少使用 var

2、命名规范

1. 命名风格

类型命名风格示例
变量名camelCaseuserList, mapLayer
函数名camelCasegetUserData()
常量名UPPER_SNAKEMAX_LAYER_COUNT
类/构造函数PascalCaseMapService, User
文件名kebab-casemap-layer.js

2. 函数命名

  • 使用动词 + 名词的形式，突出函数的行为和作用
  • 保持简洁且语义明确

正确示例：

function fetchUserData() {}
function updateMapLayer() {}
function calculateDistance() {}

错误示例：

function data() {}         // 意图不明
function doThing() {}      // 含义太泛

3、函数与模块规范

1. 函数结构建议

  • 一个函数只做一件事
  • 函数长度不宜过长
  • 尽量使用函数参数解构
function renderMap({ lat, lng, zoom }) {
    map.setView([lat, lng], zoom);
}

2. 箭头函数使用

  • 对于短小函数或回调推荐使用箭头函数
const add = (a, b) => a + b;
users.forEach(user => console.log(user.name));

3. 模块导入导出

  • 推荐使用 ES Module (import / export) 而非 CommonJS（require / module.exports）
// utils/math.js
export function calculateArea(width, height) {
    return width * height;
}

// main.js
import { calculateArea } from './utils/math.js';

4、代码风格

1. 缩进与空格

  • 格式化文档
  • 运算符、关键字之间留空格，增强可读性
if (user.isActive && user.age > 18) {
    activateUser(user);
}

2. 括号与换行

  • 使用花括号包裹所有语句块，即使是单行语句
  • 每个块状结构之间用空行分隔
if (isValid) {
    saveData();
} else {
    showError();
}

5、注释规范

1. 单行注释

// 初始化地图
const map = createMap();

2. 多行注释

/**
 * 计算两点之间的距离（单位：米）
 * 使用 Haversine 公式
 * @param {Object} pointA - 起点 {lat, lng}
 * @param {Object} pointB - 终点 {lat, lng}
 * @returns {number} 距离
 */
function calculateDistance(pointA, pointB) {
    // ...
}

6、错误处理与日志

1. 使用 try/catch 捕获异常

  • 异步函数应加错误处理，避免程序崩溃
try {
    const result = await fetchData();
} catch (error) {
    console.error('数据请求失败：', error);
}

2. 避免调试遗留代码

  • 开发时可用 console.log()，但在提交代码前应清除所有调试日志

7、数组与对象操作

  • 推荐使用 ES6 数组方法（map、filter、reduce 等），避免传统 for 循环除非性能关键
  • 对象赋值使用解构与展开（spread）操作符
const newUser = { ...user, isActive: true };
const names = users.map(u => u.name);
